# 28. 复刻交易日历（bridge/calendar.py）

> 目的：本地独立运行也能精确判断“是否交易日 / 上一交易日 / 下一交易日”，
> 供 review / closeout 的复盘日与预期交易日换算（替代简单的 +1 天，避免周末/节假日算错）。

## 1. 自包含日历模块 `bridge/calendar.py`
数据源优先级：
1. **权威缓存** `data/tmp/calendar.json`（含节假日/调休，优先）。
2. 缓存缺失或目标日期晚于缓存：**周末规则**近似（周末必休、工作日照常，不误伤未来）。

提供：
- `is_trading_day(d)`：周六/日 → False；有缓存则按缓存精确（含春节/国庆等）；
  缓存缺失/过期 → 工作日按 True 放宽。
- `previous_trading_day(d)` / `next_trading_day(d)`：向前/后跳过非交易日（至少跳过周末）。
- `load_trade_dates()` / `cache_path()` / `data_dir()`：缓存读写。

数据根与 `expectation_store` 一致 = `D:\PROJ\PT\data`（`PTRADE_EXPECTATION_DATA_DIR` 可覆盖）。

## 2. 权威收盘缓存（一次性导出）
`research/expectation/calendar_export_research.py`：在 **Ptrade 研究模块**粘贴运行，
用内建 `get_trade_days(start, end)` 导出全市场交易日（含节假日/调休）→ `data/tmp/calendar.json`，
再把研究目录里该文件下载回 `D:\PROJ\PT\data\tmp\calendar.json`。之后本地日历即精确。

## 3. 接入点
- `build_expectation_bridge._next_date(date)`：由“明天(+1)”改为 `bridge.calendar.next_trading_day`，
  review 的预期交易日自动跳过周末/节假日。
- CLI 新增子命令查询：
  ```
  py -3.10 build_expectation_bridge.py calendar [--date 2026-10-16]
  ```
  打印：当日是否交易日 / 上一交易日 / 下一交易日 / 本地缓存是否存在。
- `closeout_review` 复用的 `_next_date` 同步生效。

## 4. 已实测
- `2026-10-16`（周五）：trading=True，prev=10-15，next=10-19（下周一）—— 无缓存时正确跳过周末。
- 日历缓存未生成时按周末近似；生成权威缓存后含节假日精确判定。

## 5. 局限
- 无缓存时节假日不精确（春节/国庆等），务必用研究模块 `get_trade_days` 导出权威缓存覆盖。
- 本地脚本 `calendar` 查询依赖本地缓存文件；若未导出，跨节假日判断只能按周末。
