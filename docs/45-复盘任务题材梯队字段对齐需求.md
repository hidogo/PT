# 复盘任务题材梯队字段对齐需求（对接 AXquant，2026-10-26）

> 提出方：PT buysell_core（v0.79）。本需求供 AXquant 复盘任务按 PT 现有策略消费规则匹配生成，
> 消除 10-26 发现的口径漂移。PT 侧 P1（加载防收缩）与消费行为已由 selftest T130a-e 锁定。
> 数据契约基准：`research/expectation/export_lianban.py` 的 `zt_lianban_latest.csv` 与
> `derive_closing_board_status`（AXquant/axquant/strategy/expectation/publish.py）。

## 1. 背景与根因

10-26 版 `zt_lianban_latest.csv`（59 只）中 600094 大名城（2 板）被标 `unique_high=1`。
按 PT 策略消费口径核对：
- 地产/基建 题材（themes 全量）：成员 600838（4 板）/600094（2 板）/300949（1 板）-> 组内最高身位是 600838，唯一；
- AI/数据要素/算力 题材：3 只 2 板（000810/600094/605488）并列最高 -> 无唯一。
- 即 600094 在任一所属题材内都不是「最高身位唯一」，`unique_high=1` 为误标。

根因：`derive_closing_board_status` 的分组口径是「涨停原因关联权威板块（主因）」，而 PT 消费/兜底
（`_annotate_zt_uniqueness`、`_dyn_theme_status`）用「themes 全量归并（theme.buckets）」。
600838 主因「商贸零售」未并进 600094 的「房地产开发」组，导致组内最高被误判。
误标会穿透 PT 中位规避（`_mid_board_avoid`：2-5 板 + unique_high 豁免）。

## 2. R1：unique_high 判定分组口径 = themes 全量归并

要求 AXquant 复盘任务生成 `unique_high` 时，分组与 `themes` 列（theme.buckets 归并）同源，
而不是涨停原因主因分组。

规则（与 PT `_annotate_zt_uniqueness` 兜底逐条一致）：
- 分组：以题材为节点、共享成员并组（连通分量）；每股按 `themes` 全量归入其全部题材。
- 判定：组内最高身位唯一（`len(top)==1`）且（组内≥2 家 或 全市场最高身位唯一）-> `unique_high=1`。
  - 并列最高（组内多只同身位）不授；
  - 单票组且非全市场最高不授；
  - 高度压制到 3/4 板等「全市场最高身位唯一」场景仍授（与既有特例一致）。
- 身位 = `board_cnt`（T-1 连板数），与现有 `derive_closing_board_status` 的 `code_heights` 一致。

验收（以 10-26 数据重算）：
| code | board_cnt | 应授 unique_high | 现文件 |
|---|---|---|---|
| 600838 上海九百 | 4 | 1（地产/基建组最高唯一） | 1 |
| 600094 大名城 | 2 | 0（地产非最高 / AI 并列） | 1（需修正） |
| 其余中位非唯一股 | 2-5 | 0 | 0 |
