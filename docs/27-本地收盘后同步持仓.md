# 27. 本地收盘后同步持仓（PTrade 客户端 API）

> 结论：**能**。本地通过 PTrade **客户端侧 Quant API**（见 docs/22）查询账户持仓，
> 收盘后即可同步为本地 JSON，供本地复盘 / 预期（review --positions）消费。
> 与 AXquant 走「QMT 交易端桥」不同，这套是直接连 PTrade 客户端连接通道。

## 1. 原理
- `PTradeQuantApi.get_engine()` 建连（断线 60s 重试）→ `get_positions()` 拉全部持仓。
- 持仓/可用数量是**账户侧数据**，不依赖盘中行情，收盘后仍可查（即“收盘持仓”）。
- 依赖：PTrade 客户端本机已登录并连接服务端；Python 3.7 + API 目录
  `D:/gjzq/ptrade/Libs/Python/api/`（`PTradeQuantApi.py` + `PTradeQuantCore.cp37-win_amd64.pyd`）。

## 2. 用法
```text
"D:/gjzq/ptrade/Libs/Python/api/Libs/Python/python3/python.exe" ^
  D:\PROJ\PT\research\expectation\sync_positions.py --date 2026-10-16
```
- 输出：`D:\PROJ\PT\data\positions\positions_<date>.json`
  包装 `{positions:[{code,name,amount,enable_amount,cost,last,market_value}], portfolio, ...}`。
- 代码口径：统一为 AXquant 的 `.SH/.SZ/.BJ`（数字前缀推断 + 后缀映射），与
  `bridge/publish.normalize_code` 兼容。
- 可选 `--out` 指定输出、`--api-dir` 覆盖 API 目录。

## 3. 与本地复盘/预期的衔接
- `review` 子命令默认读取 `data/positions/positions_<当日>.json`（`_default_positions`），
  存在即当作持仓输入；也可显式 `--positions <file>`。
- 端到端：收盘后 `sync_positions.py` → `build_expectation_bridge.py review --date <T>` →
  待上传 CSV → 定时上传（选取 `ptrade_bridge\`）→ 云策略确认。

## 4. 验收
- 先启动并登录 PTrade 客户端（连接服务端）。
- 运行脚本，核对自动打印的持仓列表（code/名称/qty/cost/last）与客户端界面一致。
- 确认输出 JSON 中 `positions` 数组与 `portfolio` 数值正确。

## 6. 收盘后一键流程（closeout_review.py）
把「同步持仓 -> 本地复盘 -> 预期 CSV」融合成单条命令：
```text
"D:/gjzq/ptrade/Libs/Python/api/Libs/Python/python3/python.exe" ^
  D:\PROJ\PT\research\expectation\closeout_review.py --date 2026-10-16
```
- 步骤1：`sync_positions.run_sync()` 拉收盘持仓 `data/positions/positions_<date>.json`。
- 步骤2：`build_expectation_bridge.review` 复盘（默认读步骤1持仓）-> 预期 JSONL -> 待上传 CSV。
- 可选：`--skip-sync` 仅复盘；`--open-reason/--snapshots/--insights/--out-dir` 覆盖输入输出。
- 用 API 自带 Python3.7 运行（保证 PTradeQuantCore.pyd 兼容）；已用 `--skip-sync` 跑通复盘步骤，
  同步步骤需实机登录客户端后验证。

## 7. 局限
- 客户端 API 快照延迟 / 低频，适合**持仓管理 / 收盘同步 / 日级决策**，不适合高频打板。
- 需客户端本机在线连接；断线会走 60s 重连循环。
- 首次运行请确认 Position 实际字段名（symbol/amount/enable_amount/cost_basis/last_sale_price），
  若券商版本字段有差异，`sync_positions.py` 的 `_record` 会自动兜底为 0/空。
