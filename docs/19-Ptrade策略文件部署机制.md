# Ptrade 策略文件部署机制

## 1. 部署架构（云端托管）

- PTrade 客户端（Windows）本地运行，但**量化模块为云端部署**：客户端通过 HTTP/HTTPS 连接券商云服务器。
- 客户策略部署在券商服务器，策略文件**加密存储**，并用 **Docker 容器**隔离各账号运行空间（运行环境与资源独立）。
- 云端部署 → 策略**无法与本地路径直连**，只能读写服务器的「研究目录」（get_research_path()，Linux 根路径形如 /home/fly/notebook/）。

## 2. 策略文件形态与上传

- 仅支持 Python（当前常见 Python3.11.4；以券商为准）。
- 一个策略 = 一个 UTF-8 文本策略文件（.py），内含 initialize / handle_data 等生命周期回调；终端「新建策略」从模板创建，也可从研究目录上传/下载。
- 依赖文件（如 csv 底仓、数据文件）也需上传到「研究」目录，策略内用 get_research_path() 引用。
- 上传方式：
  - 手动上传/下载：单个文件，**≤50M**；暂不支持文件夹，需逐个上传。
  - 定时上传：研究环境可定时从本地路径读文件上传，**次数由券商配置**，不支持高频；同样 ≤50M/文件。
- 校验：check_strategy(strategy_path="./strategy.txt") 可检查策略内容；传入路径时要求策略文件已上传至研究且为 UTF-8 文本。

## 3. 上线 / 托管运行

1. 新建回测：设开始/结束、资金、基准、频率 → 引擎跑历史验证。
2. 新建交易：交易界面新增交易并绑定策略 → 系统把策略部署到券商服务器，开始托管运行。
3. 托管运行在服务器，客户端可关闭；服务器负责调度、数据、持久化、下单。
4. 服务器异常/重启时默认**自动重拉本交易**（not_restart_trade=0 执行；=1 不执行）；重拉时重跑 initialize 与 before_trading_start，可用 server_restart_not_do_before=1 让 before_trading_start 当日仅执行一次。

## 4. 对开发者的含义

- 没有本地文件直连：一切临时/持久化数据读写集中于研究目录（get_research_path()）+ 框架自动持久化（g）。
- 三方库用券商白名单；无 torch/LLM（见 docs/14）。
- 上传/读写频率受限 → 不能靠高频本地文件喂数据；外置 AI/外源数据需用 Ptrade 内置数据接口或（极少数券商）外连。
