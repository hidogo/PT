# 预期三态对接流水线设计 —— AXquant 竞价终态 → 文件 → 定时上传 → Ptrade 开盘确认 → 执行

> 目标：把 AXquant 的「次日预期三态（竞价终态）」跨系统喂给 Ptrade 托管，次日开盘按确认结果执行买卖；
> 优先用 Ptrade 现成标准函数，少自己造。关联：docs/12、19、17、strategies/buysell_core。

## 一、总体流水线（异步，分三段）
  AXquant(本机)                    Ptrade 研究(云端)                Ptrade 托管策略
  1) 收盘后算 T+1 预期(竞价终态/类型)   4) 定时上传本地文件到           5) 开盘 get_research_path() 读文件
  2) 确认后写本地交互文件     /data/expectation_<生成日期>.csv + expectation_latest.csv        6) 竞价确认(竞价/涨停/封单)
  3) 文件落 data/expectation 目录     <-- 研究环境定时上传 -->       7) 命中 -> 执行买卖(order,DO_ORDER门控)

关键点：三段时间解耦（时差一天），靠“文件 + 定时上传”异步交接；窗口内多策略不交互，交接只能经研究目录文件（docs/12）。

## 二、交互文件契约（Ptrade 消费格式）
文件：研究目录 /data/expectation_<生成日期>.csv，UTF-8，含表头。字段（对齐 AXquant expectation）
>文件命名以“生成日期”为准：本地生成时按生成日 (YYYY-MM-DD) 命名，并写出稳定指针 expectation_latest.csv。云端优先读 latest，旧《当日交易日》命名文件仍作兑底。
| 字段 | 取值 | 说明 |
| code | 600570.XSHG | 标的（统一 .XSHG/.XSHE） |
| side | buy/sell/hold | 预期动作 |
| entry_type | normal/one_word_board | 普通/一字板 |
| expected_status | pending_exceed/pending_meet/pending_miss | 竞价预期三态 |
| yesterday_open_pct | 3.2 | 昨日开盘涨幅% |
| expected_auction_change_pct | 6.0 | 竞价预期涨幅% |
| seal_amount_t0 | 1200000 | 一字板封单量基准(T日) |
| board_name / reason | 华为鸿蒙 | 板块名 / 逻辑备注 |

## 三、Ptrade 侧实现（buysell_core v0.8）
- before_trading_start：读 /data/expectation_latest.csv（先）或 expectation_<生成日期>.csv；缺失/解析失败自动跳过（不回窗，扫描兜底）。
- v0.26c 候选顺序：`expectation_latest.csv` > `expectation_<验证日 T>.csv` > `expectation_<生成日 T-1>.csv`（即「昨日复盘文件，今日验证」；生成日命名与上文契约一致）。
- v0.27 涨停池扩展：`_synth_pool_expect` 在竞价后对 T-1 涨停池（zt_lianban）做三态初步确认——竞价涨幅>昨日开盘涨幅=pending_exceed（观察）、绿开=pending_miss（放弃）、其余=pending_meet；供方文件条目优先不覆盖；批量快照预置竞价涨幅缓存，避免 09:25 逐只拉趋势接口。`_try_expected_buys` 供方推荐优先，涨停池合成按「分最高、最主动（最早触板）」排序后置。
- after_open_probe(09:31)+首bar：文件内 code 逐条“竞价确认”：get_trend_data(stocks=code).hq_px/昨收 得真实竞价涨幅；
  按 fast_up_ratio 与 expected_status 比对定命中(exceed/meet/miss)；一字板用 get_gear_price 买一档 vs seal_amount_t0（>=1.2 超预期，<=1/3 封单衰竭）。
- 命中动作并入现有买卖通道执行（DO_ORDER=False 只记 [may-order]）；与 候选B 全市场扫描并存，扫描兜底。

## 四、用的现成标准函数
| 环节 | 标准函数 |
| --- | --- |
| 定位/读文件 | get_research_path() / get_trading_day() / 内建 open |
| 竞价确认 | get_trend_data(stocks=code) [hq_px/昨收] |
| 涨停/一字 | get_snapshot[up_px] / check_limit |
| 封单 | get_gear_price（仅交易） |
| 两分钟上攻 | get_price(1m) |
| 执行 | order / on_order_response / on_trade_response（DO_ORDER 门控） |
| 跨系统交接 | 研究环境“定时上传”（docs/12，次数受限/<=50M） |

## 五、落地分工
1. AXquant(本机)：在收盘写预期处，额外 dump 一份上述 CSV 到本地 data/expectation_tomorrow.csv（已有 position_expectation JSONL，加一行导出即可）。
2. 本机→研究目录：Ptrade“定时上传”将本地文件传成 /data/expectation_<生成日期>.csv 与 expectation_latest.csv（频率受券商配额）。
3. Ptrade 托管：v0.8 读取+确认+执行（本方案已含）。

## 六、风险与降级
- 上传配额低/迟到：文件缺失=未命中预期单，仍有全市场扫描兜底（不回窗）；
- 竞价权限/签名差异：get_trend_data 失败回退 开盘/昨收 近似（沿用 v0.7 口径）；
- get_gear_price 回测不可用：一字封单只在交易验证；普通标的 expected_status 回测可近似；
- 时区/T+1 边界：文件命名日期以“生成日期”为准；云端考量量接收 latest 时校验其内部 trade_date 与従需概期日一致，上报前校验。
