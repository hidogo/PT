# 39-供方数据缺口矩阵（全量供方逐条核对）

> 目标：把 PTrade 托管策略消费的所有数据供方逐条列出「字段契约 → 云端消费点 → 缺口/风险」，
> 供盘前勾选与验收定位。跨链路的 AXquant 复盘对接细节见 docs/34。

## 0. 结论速览（TL;DR）

- **预期文件（竞价超预期消费项）字段已齐**：`expected_auction_change_pct` 与 `yesterday_open_pct`
  两列都承载「S 日（复盘日）自身开盘涨幅 open(S)/close(S-1)-1」，即 T+1 验证日的「昨日开盘基准」，
  正是 `_eval_auction`（chg>yopen 判竞价超预期）与 `_auction_benchmark`（达标基准）的消费项。
  **文件包含该项；云侧另有 1d 历史兜底**（`_hist_window`，需 ≥2 根）。
- **真正缺的不是字段，是「文件当天没到云端」**：10-20 全天 `expectation file not found`，
  根因是上传链路/文件名轴（无 latest、只有 `expectation_2026-10-19.csv` 生成日命名），v0.26c 已加
  latest > 验证日 > 生成日 三级候选；明日 10-21 前必须上传 `expectation_2026-10-20.csv` 或 latest。
- **结构性盲区（非字段缺，需接受或补本地值）**：次新股 1d 历史不足 2 根 → 竞价超预期基准缺失，
  涨停池三态对该类永远 `pending_meet`；5 日低吸需 ≥9 根历史 → 次新直接不触发。
- **待办缺口（可改代码消除）**：涨停池合成未过滤 ST（`is_st` 字段已有但未消费）；板块归属只取
  首层首个板块代码，可能漏更强板块；板块强度=成员实时涨跌均值，未含成交额/换手权重。
- **灵敏度天花板**：L2 无订阅模式（docs/37 已复核），3s 帧轮询为上限，亚秒级不可行；
  「事件驱动下单 <3s」不可行。

## 2. A1 预期文件逐列核对（响应标注：是否含 T 日开盘涨幅）

CSV 列：`code, side, entry_type, expected_status, yesterday_open_pct,
expected_auction_change_pct, seal_amount_t0, board_name, reason, sell_policy_hint`

- `expected_auction_change_pct` ← 导出时 `_fmt_empty(r.auction_change_pct)`，即 S 日自身开盘涨幅
  （`build_expectation_bridge._correct_yopen` 已按 `open(S)/close(S-1)-1` 回填）。**这就是 T+1 竞价超预期的消费基准**。
- `yesterday_open_pct` 同值（S 日开盘涨幅）。云端 `_eval_auction`：`chg>yopen → 竞价超预期`（负基也判高开，v0.17）。
- 云端兜底：`_yesterday_open_chg` / `_auction_benchmark` 在文件缺失该列时用 `_hist_1d`（≥2 根）折算；
  `_confirm_expected` 在基准缺失或 ≤0 时不误弃也不达标（等盘中），避免过触发。
- 实测样例（10-19 生成、10-20 消费）`603690.XSHG hold pending_meet 6.98 6.98`：两列同值=S 日开盘涨幅 6.98%。
  ⚠️ 注意与 AXquant review 存值的「2 天滞后差」问题已在 docs/33 修正为 S 日口径，两列保持一致；
  若未来想用「预期目标涨幅 ≠ S 日开盘涨幅」作为达标基准，两列才需要拆开。

### A1 缺口
- **文件到位是硬前提**：10-20 全天缺失 = 没上传/命名轴。盘前勾选：`run_one_click_after_close.py --date 2026-10-20`
  生成 → 确认 `data\ptrade_bridge\expectation_2026-10-20.csv` 已传 → 云端 `expectation_2026-10-20.csv` 命中。
- **次新股无基准**：本地若也不填（position_expectation jsonl 无 auction_change_pct/yesterday_open_pct），
  云端 1d 历史不足 2 根 → 该类永不判竞价超预期。可选：供方对次新显式填昨日开盘涨幅。

## 3. A2 涨停池逐列核对

CSV 列：`date, code, name, board_cnt, limit_up_time, seal_money, chg_pct, is_st, reason`

- 云端消费 `_load_zt_lianban`：board_cnt / limit_up_time / seal_money / is_st / chg_pct 全读入。
- 涨停池三态 `_synth_pool_expect`：竞价涨幅（快照 open/preclose，2 位小数防浮点）> S 日开盘基准 = pending_exceed；
  绿开 = pending_miss；其余 pending_meet；排序 `_pool_exp_priority` = 分最高、最主动（`g.first_zt[code].ts` L2 首触）。
- 一字板：`_mark_one_word_open` 09:25/09:31 快照识别（开=涨停价且卖盘空）；`_sealed_at_limit` 免 5s 门槛；core_buy 一字闸门。
- 实测：`[zt-lianban] -> 49`、`[elastic] yizi=4 strong_boards=7`、10-16 实测 59/59 不缺（docs/34 §8）。

### A2 缺口
- **ST 未过滤**：`is_st` 已读入但 `_synth_pool_expect` 未按 `is_st` 剔除 → ST 股会进涨停池观察/买入候选。
  建议补统一 `_is_st` 过滤（含预期文件、自选股、扫描池）。
- **「最主动」依赖 L2 首触**：`limit_up_time` 文件值未用于排序；L2 首触缺失时该标的后置（fallback 1e18）。
- **炸板池不在涨停池内**：`break_pool` 有意排除（docs/34 §8），反包场景走动态 watch/核心池，属设计口径。
- 日期轴：数据日 vs 云端交易日，已用 latest 指针 + 交易日别名双轴覆盖（docs/34 §9）。

## 4. A3 自选股
- `selfwatch.csv` 每行一代码（可带列），`_load_selfwatch` 只取首列并归一后缀；盘中 N bar 重读实时同步。
- 缺口：无名称/分组/优先级；池内排序只按「预期文件 exceed 优先」，自选股本身不区分权重。
