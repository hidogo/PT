# 34-数据提供方对接矩阵（AXquant 复盘任务对接 + 一致性）

## 1. 背景
PTrade 托管策略的复盘链消费「数据提供方 AXquant」的收盘/复盘产出。本契约的目标：
- **集中定义** AXquant 目录布局与路径解析（单一事实源，不再散落硬编码）；
- **前置就绪校验**：一键收盘先探活提供方输入，读不到就显性告警，避免静默用陈旧/空数据；
- **产出一致性核对**：预期 CSV ↔ 源 jsonl、涨停名单 ↔ 涨停池，行列一致才算闭环。

## 2. 提供方目录布局（对外数据契约）
AXquant 根：`env AXQUANT_PROJECT_DIR` 优先，否则同级 `D:/PROJ/AXquant`。

| 票据 | 相对根 | 文件 | 供谁消费 |
|---|---|---|---|
| 持仓复盘 | `data/review/` | `position_review_<复盘日>.jsonl` | closeout_review / build_expectation_bridge |
| 开板原因 | `data/buys/` | `open_reason_<复盘日>.jsonl` | 复盘归因 |
| 涨停特快照 | `data/special_snapshots/` | `<复盘日>.json` | 分时/节奏复盘 |
| 涨停池/连板 | `docs/review/` | `limit_up_boards_<复盘日>.json` | export_lianban → `zt_lianban_latest.csv` |
| 预期源 | `data/` | `position_expectation_<预期日>.jsonl` | run_expectation_build (from-jsonl) |

## 3. 对接层：`research/expectation/bridge/axquant_contract.py`
- `axquant_root()`：探根（env → 同级）。
- `paths(review_date, next_date)`：一次性解析全部对接触点绝对路径（含 PT 本地镜像 `data/review/` 与 `bridge_dir`）。
- `probe / missing`：逐条探活（exists/size/mtime/age_hours），返回缺失 key。
- `limit_up_rows`：读涨停池 `payload.pool.item`。
- 一致性：
  - `check_expectation_consistency(csv, jsonl)`：**数字一致**保证"同一批证券"，再按**市场族**（SH/SZ/BJ）报后缀异常；AX(`.SH/.SZ/.BJ`) 与 PT(`.XSHG/.XSHE/.XBJ`) 惯例差异不算异常。
  - `check_zt_consistency(zt_csv, review_date)`：名单行数 == 涨停池条数，且 `date` 标签 == 复盘日。

## 4. 一键流程接线：`run_one_click_after_close.py`
| 步骤 | 内容 | 说明 |
|---|---|---|
| 0 | 提供方就绪校验 `axc.probe_report` + `missing` | 缺失→告警；`--require-provider` 时缺失直接中止(rc=2) |
| 1 | 持仓同步 `sync_positions` | 需登录；`--skip-sync` 绕过 |
| 2 | 本地复盘 `closeout_review` → 预期 CSV | |
| 3 | `run_expectation_build` from-jsonl→validate→上传 CSV | |
| 4 | `export_lianban` → `zt_lianban_<当日>.csv` + `zt_lianban_latest.csv` | |
| 5 | 产出一致性核对 | 打印 预期/名单 的 ok 与差异 |

示例：
```
python research/expectation/run_one_click_after_close.py --date 2026-10-16 \
    --skip-sync --source data\position_expectation_2026-10-19.jsonl --out-dir <临时>
```

## 5. 代码后缀归一（AX ↔ PT 一致性核心）
- AX：`.SH/.SZ/.BJ`；PT：`.XSHG/.XSHE/.XBJ`。
- 各消费点（export_lianban / bridge 导出 / contract 核对）统一按**数字 + 市场族**判断归属，避免"数字相同但后缀写错"静默通过：
  - 深市族：`000/001/002/003/300/301` → `.XSHE/.SZ`；
  - 其余沪市为主 → `.XSHG/.SH`（北交 8xx/4xx/920 另记 `.XBJ/.BJ`）。
- 实测干净：AXquant 源与 PT 本地均为 `.SH/.SZ`（含 `000530.SZ` 正确），上传 CSV 为 `.XSHG/.XSHE`，归一后 5/5、59/59 全一致。

## 7. 边界/提醒
- AXquant 分 `data/review`、`data/buys`、`data/special_snapshots`、`docs/review` 四个子目录，**目录结构即对外数据契约**；AXquant 改布局前须同步本表，否则 PT 读空（只告警不报错）。
- 提供方探活为只读校验，不自动拉起 AXquant 复盘（复盘依赖 QMT 行情/持仓，需其自身任务链）；如需硬性前置，用 `--require-provider`。
- 持仓同步是唯一依赖登录的外部依赖；复盘→预期→名单其余链路可离线确定性复现。

## 8. 涨停数据完整性（防遗漏）
- 实测 10-16：`pool.item=59`、`pagination.total=59`、`summary.pool_total=59`（单页 size=200），
  `pool∩break=0`（炸板 48 只在 break_pool,正确排除），`meta.generated_at=2026-10-16T15:29`（收盘终态）。无遗漏。
- 护栏：`export_lianban._pool_missing` 校验 `item < pagination.total` 即抛错中止，不写半份名单（防涨停数超分页 size 时静默截断）。
- 其余潜在遗漏源与应对：提供方 json 缺失/陈旧 → 云端 `_load_zt_lianban` 回退 1d 历史（`verify_provider` 步骤0 探活 + 时效）；收盘前运行会取到未终态涨停池 → 建议终态(after 15:30)后再跑一键收盘。
- selftest T35：真实 59/59 不缺、伪造 item3/total100 检出缺 97。

## 9. 待上传目录文件名一致性（D:/PROJ/PT/data/ptrade_bridge）
命名存在两个日期轴，需对齐：
- `expectation_<生成日期>.csv / expectation_latest.csv`：T = 云端消费当日（今天）。当前 `expectation_2026-10-19.csv` 正确（trade_date=10-19, review_date=10-16）。
- `zt_lianban_<复盘/数据日>.csv`：S = 涨停数据日（= T 的上一交易日），如 `zt_lianban_2026-10-16.csv`。
- `zt_lianban_latest.csv`：稳定指针（云端首选），必须始终存在。
- 云端 `_zt_lianban_paths` 的 dated fallback 用 `zt_lianban_<当日交易>>.csv`，与复盘日命名轴不同 —— 已由 `export_lianban.run(alias=...)` 追加 `zt_lianban_<交易日>.csv` 别名（一键 step4 自动传 next_td）双轴全覆盖。
- `selfwatch.csv`：固定名。
- `archive/`：`expectation_<日期>.csv.meta.json` / `.normalized.jsonl` / `ptrade_today.csv`，与 source 的 trade_date 对齐。
- 校验：`verify_provider.py` 步骤B 核对名单行数与涨停池；文件名轴差异靠 latest 指针 + 交易日别名兜底。
