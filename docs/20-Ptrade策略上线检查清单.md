# Ptrade 托管策略上线检查清单（编写→上传→回测→模拟→实盘）

> 依据部署模型（见 docs/19）：客户端本地编写、量化模块云端、策略加密上传服务器、Docker 隔离、托管运行、服务器重启自动重拉交易。
> 每个阶段打勾通过后再进入下一阶段。

## 0. 阶段总览

策略研究(本地) ──▶ 回测验证(Ptrade) ──▶ 模拟交易(Ptrade) ──▶ 实盘上线(Ptrade)

---

## 1. 编写（本地）

- [ ] 终端「新建策略」，选对业务类型（股票/两融/期货/期权/港股通）并命名。
- [ ] 实现 initialize（必选）与 handle_data（必选）；按需 before_trading_start / after_trading_end / tick_data / on_order_response / on_trade_response。
- [ ] 生命周期与事件钩子行为符合预期（见 docs/03）。
- [ ] 只使用券商白名单三方库（见 docs/14）；不引入 torch/LLM、外部网络库。
- [ ] 数据只用 Ptrade API（get_history/get_price/get_snapshot/get_fundamentals/get_stock_blocks/check_limit 等，见 docs/06）；不使用本地文件直连、akshare/wencai 等外源。
- [ ] 关键逻辑用 try/except 包住并 log.info/warn，避免异常导致托管终止。
- [ ] 交易只能操作 set_universe 股票池内标的。
- [ ] 下单/限价按标的小数位取整（股票 2 位、可转债/ETF/LOF 3 位、股指期货 1 位、期权 4 位）；涨停委托用市价保护/限价+2% 笼子钳制（见 docs/07）。
- [ ] 定时任务（run_daily 与 run_interval 累计）≤5 个；run_interval 最小间隔 1s(期货)/3s(股票)（见 docs/05）。
- [ ] 持久化设计：用框架自动持久化（g）+ 手动 pickle 到研究目录；确认不会污染、跨日可恢复（见 docs/02、docs/17）。
- [ ] 预判服务器重启重拉的影响：initialize/before_trading_start 可重入；需要时设置 not_restart_trade / server_restart_not_do_before（见 docs/19）。
- [ ] 本地用 check_strategy 校验策略内容（避免首跑才暴露语法/接口问题）。

## 2. 上传（到研究/云端）

- [ ] 策略文件保存为 **UTF-8 文本 .py**。
- [ ] 上传策略文件到「研究」目录（手动逐个上传；暂不支持文件夹）。
- [ ] 依赖数据文件（csv 底仓、静态名单等）逐个上传；**每个 ≤50M**。
- [ ] 文件名避开非法字符：` : ? , @ # $ % & ( ) ; ' " < > ` ~ ! ^ * `，长度 ≤256。
- [ ] 研究目录按「数据/状态/日志」建好子目录（见下方文件规划）。
- [ ] 检查上传配额（券商配置，定时上传次数有限，不支持高频刷文件）。
- [ ] 确认策略运行时可用 get_research_path() 读取到所依赖文件。
- [ ] （可选）用 check_strategy(strategy_path="./策略.py") 对上传后的策略做云端校验。

## 3. 回测

- [ ] 新建回测：设开始/结束时间、回测资金、基准、频率（日/分钟）。
- [ ] 跑完看收益曲线、回撤、评价指标、日志。
- [ ] 多区间/多市场环境下抽样验证（牛/熊/震荡）。
- [ ] 若迁移 axquant：与 axquant 回放结果对比（量纲、账户口径），确认逻辑一致（见 docs/18）。
- [ ] 存在偏差则回到第 1 步修逻辑，收敛后再进下一步。

> 注意：Ptrade 回测按分钟/日驱动，**无法再现亚秒打板/封单微观**；打板类场景回测结果需打折扣，改用模拟盘验证（见 docs/18）。

## 4. 模拟交易

- [ ] 新建交易（**模拟盘**）并从策略列表绑定策略。
- [ ] 完整验证交易日各个环节：盘前 before_trading_start、竞价（run_daily + get_trend_data）、盘中 handle_data / run_interval / tick_data、盘后 after_trading_end。
- [ ] 验证下单→成交→持仓→对账闭环（on_order_response / on_trade_response，get_orders/get_trades/get_positions）。
- [ ] 验证持久化：跨日、退出/重启后状态（g 恢复 + 研究目录 pickle）是否正确（见 docs/17）。
- [ ] 验证服务器重启重拉行为（可人为模拟）：not_restart_trade、server_restart_not_do_before 生效。
- [ ] 观察连续 5~10 个交易日：信号频率、误触发、冷却、每日买入 N 支封顶、风控是否按预期。
- [ ] 疑似交易环境专属问题（tick 节奏、封单近似、竞价）在此阶段重标定阈值。
- [ ] 用模拟盘日志/指标确认收益—回撤特征接近回测预期后，再进实盘。

## 5. 实盘上线

- [ ] 联系券商开通实盘/相应业务权限（量化权限、两融/期权/港股通等）。
- [ ] 配置风控与紧急处置：每日买入封顶、止损/止盈、集中度、跌停不买、核按钮（P1 绿开等）。
- [ ] **小资金起步**（如 1 档/小比例），灰度一段时间再放大。
- [ ] 上线：新建交易（**实盘**）绑定策略。
- [ ] 部署确认：策略已加密部署到服务器、Docker 环境就绪、客户端可关闭。
- [ ] 盘中监控：资产/可用资金/持仓、交易日志、是否正常成交与回报。
- [ ] 确认服务器重启自动重拉策略且不再重复触发 before_trading_start（如需）。
- [ ] 建立审计/复盘：每日盘后 after_trading_end 落档 + 定期核对 get_trades_file/get_deliver/get_fundjour（对账）。
- [ ] 异常（涨停买不进、拒单、权限不足）记录并回落到模拟盘复现。

## 6. 研究目录文件规划（云端 get_research_path()）

根目录示例：/home/fly/notebook/（Linux 容器），策略内用 get_research_path() 取绝对路径。

| 子目录 | 建议 | 说明 |
| --- | --- | --- |
| data/ | 底仓 csv、静态名单、板块/名单缓存 | 低频数据，上传/更新经手动或定时上传（≤50M） |
| state/ | pickle 持久化状态（持仓天数、冷却、已买计数、预期档案、盘中最高价等） | 跨日/跨重启恢复；与 g 自动持久化配合 |
| logs/ | 策略自写审计 jsonl/日志 | 便于复盘与对账；高频写入注意配额/目录上限 |
| strategies/ | 策略源文件 .py | 与云端策略上传区对齐，便于版本管理 |

命名规范：UTF-8 文本、≤256 字符、避开 ` : ? , @ # $ % & ( ) ; ' " < > ` ~ ! ^ * `；单个文件 ≤50M；**不支持文件夹上传，需逐个传**。

读写注意：
- 云端无法直连本地路径 → 所有“需落盘”数据一律放研究目录。
- 上传/定时上传**次数受限**、单文件 ≤50M → 高频数据不要落研究目录，改走 Ptrade 数据接口或内存/g 持久化。
- 高频中间结果优先内存 + g 自动持久化，仅把低频/对账/复盘需要的内容写研究目录。
